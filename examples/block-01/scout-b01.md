# Scout notes: b01 "How language models really work"

Researched 2026-10-24. Findings marked [UNVERIFIED] came from memory or a source I could not open. Check before use.

## l1: From neural networks to attention: the story

- Backpropagation was popularised in a 1986 Nature paper by Rumelhart, Hinton and Williams. It adjusts network weights to shrink the gap between actual and desired output, so hidden units learn useful features. (Learning representations by back-propagating errors, https://inspirehep.net/literature/2171919, 1986-10)
- The maths behind backprop was rediscovered several times before 1986, with roots in the 1960s. Say "popularised" not "invented". (Learning representations by back-propagating errors, https://scholarhub.vn/publication/Learning-representations-by-back-propagating-errors/e8b4842c-7df7-4c08-b6d6-17187c644a67, 1986-10)
- Hinton, Osindero and Teh (2006) showed a fast greedy method to train deep belief nets one layer at a time. This is one of the early "deep learning revival" papers. (A Fast Learning Algorithm for Deep Belief Nets, https://www.cs.utoronto.ca/~hinton/absps/ncfast.pdf, 2006-07)
- AlexNet (Krizhevsky, Sutskever, Hinton, NeurIPS 2012) cut ImageNet top-5 error to 15.3%. It had 8 layers and about 60 million parameters, trained on two GPUs. (AlexNet, https://en.wikipedia.org/wiki/AlexNet, 2012-12; CHM AlexNet source release, https://computerhistory.org/blog/chm-releases-alexnet-source-code/, 2012-12)
- Misconception: AlexNet did not start deep learning from nothing. DanNet, a GPU-trained CNN from Schmidhuber's lab, had won image contests in 2011 on smaller datasets. (ImageNet Classification with Deep CNNs, https://lml.trendcraft-bk.duckdns.org/research/alexnet, 2012-12)
- Recurrent networks read text one word at a time. A hidden state carries the summary forward, so the early words get squeezed as the text grows. (Long Short-Term Memory, Hochreiter and Schmidhuber, https://papers.baulab.info/papers/Hochreiter-1997.pdf, 1997-11)
- LSTM (1997) added gated memory cells, a "constant error carousel", so error signals survive over 1000+ time steps. The forget gate came later, in 2000, per a secondary source. (Long Short-Term Memory, https://mlanthology.org/neco/1997/hochreiter1997neco-long, 1997-11; forget gate attribution [UNVERIFIED], 2000)
- Sequence-to-sequence (Sutskever, Vinyals, Le, NIPS 2014): one LSTM encodes the whole input into a fixed vector, a second LSTM decodes it. English-to-French reached BLEU 34.8. Reversing the source sentence words helped. (Sequence to Sequence Learning with Neural Networks, https://arxiv.org/pdf/1409.3215, 2014-09)
- Bahdanau, Cho and Bengio (ICLR 2015, arXiv 1409.0473) let the decoder look back at all encoder states with learned weights for each target word. This removed the single-vector bottleneck and matched the phrase-based system on English-to-French. (Neural Machine Translation by Jointly Learning to Align and Translate, https://arxiv.org/pdf/1409.0473, 2014-09)
- Vaswani et al. (arXiv 1706.03762, 2017-06) removed recurrence and convolutions entirely. It used only attention. Result: 28.4 BLEU on WMT 2014 English-to-German, over 2 BLEU ahead of the prior best including ensembles. (Attention Is All You Need, https://arxiv.org/abs/1706.03762, 2017-06)
- Misconception: attention was not new in 2017. Bahdanau's 2014 version was the fix for recurrent encoder-decoders. The 2017 paper made attention the whole architecture. (Neural Machine Translation by Jointly Learning to Align and Translate, https://arxiv.org/pdf/1409.0473, 2014-09)

## l2: Inside the transformer

- The 2017 transformer's scaled dot-product attention divides scores by the square root of the key dimension. Without this, big dot products push softmax into flat regions where gradients vanish. (Attention Is All You Need, https://arxiv.org/abs/1706.03762, 2017-06)
- Attention has no built-in sense of order. The original paper adds sinusoidal position vectors to the token embeddings, by addition, not concatenation. (Attention Is All You Need, https://arxiv.org/abs/1706.03762, 2017-06)
- The base transformer in the 2017 paper had 6 layers, model width 512 and 8 attention heads. [UNVERIFIED] from memory, check the paper's Table 3. (Attention Is All You Need, https://arxiv.org/abs/1706.03762, 2017-06)
- Modern models mostly replace sinusoidal positions with rotary position embedding (RoPE), which rotates query and key vectors by position. [UNVERIFIED] (Su et al., RoFormer, https://arxiv.org/abs/2104.09864, 2021-04)
- Attention builds an n by n score grid for n tokens. Compute and memory therefore grow with the square of the context length. (Attention Is All You Need, https://arxiv.org/abs/1706.03762, 2017-06; quadratic cost framing from standard practice [UNVERIFIED] as a citation)
- FlashAttention (Dao et al., NeurIPS 2022) gives exact attention with far fewer reads and writes to GPU memory. Speedups were 2.4x to 3x on GPT-2 and long-range tasks. It does not remove the quadratic compute. (FlashAttention, https://arxiv.org/abs/2205.14135, 2022-05)
- Misconception: the model does not "look up" its context like a database. Each token's new representation is a weighted mix of the other tokens' values, with weights set by query-key matches. (FlashAttention, https://arxiv.org/abs/2205.14135, 2022-05)
- Generation is a loop: predict a probability for every possible next token, pick one (greedy, or sampled with temperature), append it, and repeat. [UNVERIFIED] as a sourced claim, standard description in the Vaswani decoder design (Attention Is All You Need, https://arxiv.org/abs/1706.03762, 2017-06)

## l3: Tokens: the unit of everything

- Subword tokenisation (Sennrich, Haddow, Birch, arXiv 1508.07909) uses byte pair encoding to split rare words into smaller pieces. It removed the need for a fixed dictionary. Gains were about 1 BLEU over a back-off baseline. (Neural Machine Translation of Rare Words with Subword Units, https://arxiv.org/pdf/1508.07909, 2015-08)
- Byte pair encoding was first a data compression method from 1994 (Philip Gage). The NLP use is the 2015 adaptation. [UNVERIFIED] (Sennrich et al., https://arxiv.org/pdf/1508.07909, 2015-08)
- Karpathy's two-hour "Let's build the GPT Tokenizer" (Feb 2024) walks through BPE from scratch and lists tokenizer quirks, including why models cannot reverse strings. (Simon Willison summary, https://simonwillison.net/2024/Feb/20/lets-build-the-gpt-tokenizer, 2024-02-20)
- Models read tokens, not letters. "strawberry" splits into "st", "raw", "berry" under GPT-4o's tokenizer. Counting letters inside multi-character tokens gets close to random as strings get longer. (Why Do LLMs Struggle to Count Letters?, https://arxiv.org/pdf/2412.18626, 2024-12)
- The same text gets different token counts on different models. Claude Opus 4.7 was the first Claude model with a new tokenizer. Anthropic stated 1.0x to 1.35x more tokens. Simon Willison measured 1.46x on a system prompt and 3.01x on images. (Simon Willison's Weblog, https://simonwillison.net/2026/Apr/20/, 2026-04-20)
- Code and JSON usually cost more tokens than plain prose. Reported measured increases were about 1.45x to 1.47x on code and technical docs for the Opus 4.7 tokenizer. (Analysis: Claude Opus 4.7's New Tokenizer, https://feedbagel.com/post/analysis-claude-opus-47s-new-tokenizer-uses-147x-more-tokens-than-version-46, 2026-04 [UNVERIFIED as a secondary source])
- Anthropic offers a free token counting endpoint. Use it to measure a real client input per model instead of guessing. (Context windows, https://platform.claude.com/docs/en/build-with-claude/context-windows, undated [UNVERIFIED date])
- Rough rule for English: about 0.75 words per token, so 1000 tokens is about 750 words. Use it only for estimates. [UNVERIFIED] (Common rule of thumb, not sourced in this scout)

## l4: The context window

- Anthropic's official docs say everything counts toward the window: system prompt, every message, tool results, tool definitions, output, and thinking tokens. (Context windows, https://platform.claude.com/docs/en/build-with-claude/context-windows, undated [UNVERIFIED date])
- Models listed on the official context windows page (including Opus 4.6 and later, Sonnet 4.6 and later, Haiku 5.5) have a 1M-token window by default. Max output is 128k on those. Older models have 200k. (Context windows, https://platform.claude.com/docs/en/build-with-claude/context-windows, undated [UNVERIFIED date])
- Long-context pricing: on Haiku 5.5, prompts over 100,000 tokens cost more. Other 1M models bill long requests at standard pricing. (Context windows, https://platform.claude.com/docs/en/build-with-claude/context-windows, undated [UNVERIFIED date])
- Over-long input returns a 400 "prompt is too long" error on all models. On Claude 4.5 and later, a request whose input plus max_tokens is too big may stop mid-answer with stop_reason "model_context_window_exceeded". (Context windows, https://platform.claude.com/docs/en/build-with-claude/context-windows, undated [UNVERIFIED date])
- Context rot: Chroma's report (Hong, Troynikov, Huber, 2025-07-14) tested 18 LLMs. Reliability became less consistent as input grew, even on simple tasks. Chroma is a vendor, so treat its conclusions with care. (Context Rot: How Increasing Input Tokens Impacts LLM Performance, https://research.trychroma.com/context-rot, 2025-07-14)
- Lost in the middle (Liu et al., arXiv 2307.03172, TACL 2023): accuracy is highest when the relevant passage is at the start or end of the context, and drops in the middle. Longer contexts make it worse, even for long-context models. (Lost in the Middle: How Language Models Use Long Contexts, https://arxiv.org/abs/2307.03172, 2023-07)
- Cached prompt tokens still take up window space. Caching changes the price, not the window use. (Context windows, https://platform.claude.com/docs/en/build-with-claude/context-windows, undated [UNVERIFIED date])
- Cache prices (Anthropic prompt caching page): 5-minute write is 1.25x base input price, 1-hour write is 2x, and a cache read is 0.1x by default. Newer models: 0.05x on Opus 5.5 and Sonnet 5.5, 0.025x on Fable 5.1 and Mythos 5.1. Cache prefix order is tools, then system, then messages. (Prompt caching, https://platform.claude.com/docs/en/build-with-claude/prompt-caching, undated [UNVERIFIED date])
- Server-side compaction is in beta for Claude 4.6 and later and summarises earlier parts of a chat so the conversation can run past the window. Context editing (beta from 2025) clears old tool results and old thinking blocks. (Context windows, https://platform.claude.com/docs/en/build-with-claude/context-windows, undated [UNVERIFIED date]; Context editing, https://platform.claude.com/docs/en/build-with-claude/context-editing, 2025-06 [UNVERIFIED for the beta date])

## l5: From base model to assistant to reasoning model

- InstructGPT (Ouyang et al., OpenAI, arXiv 2203.02155, 2022-03) fine-tuned GPT-3 first on human-written demonstrations, then with reinforcement learning from human feedback. Raters preferred the 1.3B InstructGPT model over the 175B GPT-3 model. (Training language models to follow instructions with human feedback, https://arxiv.org/pdf/2203.02155, 2022-03)
- A base model only continues text. Ask it a question and it may write more questions. The assistant behaviour comes from post-training. (Training language models to follow instructions with human feedback, https://arxiv.org/pdf/2203.02155, 2022-03)
- Constitutional AI (Bai et al., Anthropic, arXiv 2212.08073, 2022-12) uses a written list of principles. The model critiques and revises its own answers, and an AI-labelled preference model guides reinforcement learning (RLAIF). The paper's main experiments used a 52B model per a secondary source. (Constitutional AI: Harmlessness from AI Feedback, https://arxiv.org/abs/2212.08073, 2022-12)
- Human raters often reward evasive answers to harmful requests. Constitutional AI was partly a response to that. (Constitutional AI: Harmlessness from AI Feedback, https://arxiv.org/abs/2212.08073, 2022-12)
- DeepSeek-R1 (arXiv 2501.12948, 2025-01; Nature, 2025-09-17) showed reasoning can grow from pure reinforcement learning with no human reasoning examples. The R1-Zero variant had readability and language-mixing problems. The team used GRPO, which needs no separate critic model. (DeepSeek-R1 incentivizes reasoning in LLMs through reinforcement learning, https://www.nature.com/nature-index/article/10.1038/s41586-025-09422-z, 2025-09-17)
- Test-time compute: Snell et al. (arXiv 2408.03314, 2024-08; ICLR 2025) found adaptive per-prompt compute can beat best-of-N by more than 4x. On some problems a smaller model with extra compute beat a 14x larger model. The gains depend on prompt difficulty. (Scaling LLM Test-Time Compute Optimally, https://arxiv.org/pdf/2408.03314, 2024-08)
- Adaptive thinking on current Claude models: Opus 4.7 accepts only adaptive thinking, and the old fixed budget_tokens setting is refused. Effort levels are soft guidance, with default high. Thinking tokens count as output tokens and toward the window. (Adaptive thinking, https://platform.claude.com/docs/zh-TW/build-with-claude/adaptive-thinking (translated mirror), undated [UNVERIFIED date]; Context windows, https://platform.claude.com/docs/en/build-with-claude/context-windows, undated [UNVERIFIED date])
- OpenAI (2025-09-05, "Why language models hallucinate") says training and scoring reward confident guessing over admitting uncertainty. In the GPT-5 SimpleQA comparison, one model abstained 52% of the time with a 26% error rate, while o4-mini abstained 1% with a 75% error rate. (Why language models hallucinate, https://openai.com/index/why-language-models-hallucinate/, 2025-09-05)
- Scaling laws: Kaplan et al. (OpenAI, arXiv 2001.08361, 2020-01) found loss falls as a power law with model size, data and compute. This is the basis for the large training-cost story. (Scaling Laws for Neural Language Models, https://arxiv.org/pdf/2001.08361, 2020-01)
- Chinchilla (Hoffmann et al., 2022) argued models should train on more data than Kaplan suggested. Not verified in this scout. [UNVERIFIED] (Chinchilla, arXiv 2203.15556, 2022-03)
